# Слепая проверка тегов/сентимента — руководство (Refs #57)

Локальное приложение для честной слепой проверки, которую требует гейт сентимента в
`docs/research/audiobook/m4-plan.md` (§2, §3, M4-T4): не менее 8 слепых пар, вердикт выносит
владелец, провал если он различает варианты в пользу неквантованного более чем в 6 случаях из 8.
Раньше владелец слушал файлы в файловом менеджере и видел их имена — слепота терялась.

## Запуск

```bash
make sentiment-survey
```

Одна команда: стартует локальный HTTP-сервер на `127.0.0.1:8877` (стандартная библиотека
Python, без Flask и прочих зависимостей — `.venv-tts`'s Python 3.12 достаточно) и открывает
браузер. Остановить — `Ctrl+C`. Порт можно поменять: `python3 src/sentiment_survey/server.py 9000`.

**Аудио не генерируется.** Приложение только читает уже существующие `.wav` из `output/` —
безопасно запускать, даже если GPU занят другим прогоном.

## Что откроется

Список наборов заданий, отсортированный по приоритету:

1. **`unheard_sfx_env`** — 9 `sfx:*` + 2 `env:*` тегов, которые человек ещё ни разу не слышал
   (issues #116, #119). Автообнаружено сканированием `output/m4_tag_catalog/tag_sfx_*.wav` /
   `tag_env_*.wav`.
2. **`disputed_tags`** — теги из групп B/C объективной триажи M4-T5 (слабый/неоднозначный сигнал
   по F0/темпу/паузам): `arousal`, `confusion`, `helplessness`, `longing`, `expressive_high`,
   `pause`, `singing`, `anger`, `enthusiasm`. Список выводится автоматически из
   `docs/guides/tag_reference.md`, не зашит в код.
3. **`final_intonation`** и **`boundary_check`** — завершающая интонация (метрика зашумлена
   скрипучим голосом нейтральной базы этого прогона — решает только слух) и проверка, не
   переоткрывается ли тег эмоции на границе куска текста.
4. **`stress`** — 22 клипа, 3 пары омографов (замок/стоит/атлас) × до 6 нотаций ударения.
5. Всё остальное: уже частично подтверждённые теги (группа A), второй независимый прогон
   `output/m4_tags/`, первая проверка `output/m4t0_*`, бонусный набор «эмоция против эмоции».

Каждый набор показывает `отвечено / всего`; уже пройденный набор можно открыть заново и
переслушать (заново отвеченные задания перезаписывают старый ответ по `task_id`).

## Как отвечать

- Клипы проигрываются без подписи — только «Клип 1» / «Клип 2» (порядок A/B рандомизируется на
  старте сервера, чтобы не выработалась привычка угадывать по позиции).
- Варианты ответа зависят от типа задания (парное сравнение «отличаются ли?», парное сравнение
  «какой из двух...?», одиночная оценка «слышен ли здесь шёпот?» и т.п.) — тип и текст вопроса
  берутся из набора заданий, не из кода.
- Если у задания уже есть более ранний устный вердикт владельца (докопировано из
  `docs/guides/tag_reference.md` / `m4-sentiment-results.md`), под вопросом появляется пометка, а
  в списке ответов — дополнительная кнопка «Пропустить — уже есть более ранний вердикт». Сам тег
  эта пометка не раскрывает — только то, что по нему уже что-то известно; конкретика открывается
  после ответа (или после пропуска), как обычно.
- После ответа сразу раскрываются скрытые метаданные: какой тег/вариант это был, что показывают
  метрики, совпал ли ответ с ожидаемым результатом.
- Клавиши: **1–9** — выбрать вариант ответа по номеру, **R** — переслушать первый клип сначала,
  **Enter** — перейти к следующему заданию после раскрытия ответа.
- Закрыть вкладку и вернуться позже можно в любой момент — уже отвеченное не переспрашивается
  (пока сервер работает с тем же `output/sentiment_survey_results/`; если сервер перезапущен,
  прогресс всё равно читается заново с диска при каждом старте).

## Куда пишутся результаты

`output/sentiment_survey_results/<набор>/` (каталог не попадает в Git — `output/` в
`.gitignore`):

- `answers.jsonl` — машиночитаемый, один JSON-объект на строку: `task_id`, тип задания, текст
  вопроса, ответ владельца, `listen_ms` (сколько слушал), отметка времени, скрытые метаданные,
  ожидаемый ответ (если есть) и совпадение с ним.
- `answers.md` — человекочитаемый отчёт с той же информацией в виде таблицы + список раскрытых
  метаданных по каждому заданию.

Оба файла переписываются **атомарно** (временный файл + `os.replace`) после каждого ответа —
прерванная сессия не портит уже записанные ответы.

## Сводка по набору

По завершении набора показывается: сколько заданий отвечено, сколько пропущено как уже
известное, сколько пар «различил / не различил» (для гейта из `m4-plan.md` — порог "не более 6
неразличённых из 8"), и по заданиям с известным правильным ответом (ударения, завершающая
интонация, парные "какой из двух...") — доля совпадений с ожиданием.

## Как добавить новый набор заданий

- **Материал уже лежит в `output/m4_tag_catalog/` или `output/m4_tags/`** — ничего добавлять не
  нужно, `src/sentiment_survey/catalog.py` пересканирует каталоги при следующем запуске сервера.
- **Новый прогон в новом каталоге `output/...`** — добавьте функцию-сканер в `catalog.py` по
  образцу существующих (`build_m4t0_set`, `build_boundary_check_set`): никогда не сравнивайте
  клипы из разных прогонов друг с другом, используйте локальную нейтральную базу того же
  прогона/каталога, если она есть.
- **Вопрос сложнее, чем «отличаются ли эти два клипа»** (тройное сравнение с эталоном,
  специфичная формулировка) — добавьте `.json`-файл в `src/sentiment_survey/task_sets/` по
  образцу `stress.json`/`final_intonation.json`; схема описана в комментариях `server.py`
  (`TaskSet._validate`).

## Перенос вердиктов в `tag_reference.md`

Каждая запись в `answers.jsonl` содержит `hidden.A.tag` (или `hidden.A.marker`/`hidden.A.word`
для наборов вне каталога тегов), ответ владельца и совпадение с ожиданием — этого достаточно,
чтобы вручную или скриптом сверить со статусами в `docs/guides/tag_reference.md` §2 и обновить
строки «Статус проверки на слух». Сам перенос это приложение не делает.
